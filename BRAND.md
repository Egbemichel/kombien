# Brand Policy

This document explains the relationship between Kombien's **software license** and its **brand/trademark policy** — they are separate, and this distinction matters for anyone reusing this project's code or assets.

> The full brand system (strategy, voice, logo, color, typography) lives in [brand/](brand/README.md). This file is the policy summary; that directory is the working reference.

## Software license vs. brand policy

- The **software license** ([LICENSE](LICENSE): **MIT**) governs what you may do with the *code* in this repository — copying, modifying, and redistributing it, with attribution and no warranty.
- The **brand policy** (this file) governs what you may do with the Kombien *name, logo, and visual identity* — independent of what the software license permits.

Permission to use the code does not imply permission to use the name or logo in a way that suggests your project is Kombien, is affiliated with Kombien, or is endorsed by Kombien.

## Decisions

The following were previously open questions. They're now decided:

| Question | Decision |
|---|---|
| Software license | **MIT** — see [LICENSE](LICENSE). Simple, permissive, standard for a community passion project. |
| Brand asset license | Brand assets (name, logo, wordmark, tagline) are **not** covered by the MIT code license. They remain the project's own identity — see [Using the Kombien name and identity](#using-the-kombien-name-and-identity) below. |
| Trademark clearance | **Final.** Reviewed with a legal professional and confirmed clear — see [brand/strategy/naming.md](brand/strategy/naming.md). Kombien is the name for all purposes, including registration and app-store submission. |
| Final tagline | **"Je paie combien?"** — approved for in-product use. See [brand/strategy/naming.md](brand/strategy/naming.md). |
| Final logo direction | A typographic identity built from the wordmark and the negotiation/question-response motif — no literal taxi/map/steering-wheel imagery. Artwork itself isn't produced yet. See [brand/logo/README.md](brand/logo/README.md). |
| Final colors and type weights | Approved — see [brand/colors/palette.md](brand/colors/palette.md) and [brand/typography/README.md](brand/typography/README.md). |
| Franglish in the default product experience | Yes, scoped — default in cultural/community-facing copy, not in functional UI strings. See [brand/voice/franglais-guidance.md](brand/voice/franglais-guidance.md). |
| Monorepo vs. brand-assets-only repo | **Monorepo** — this repository will hold application code alongside the brand system as the project grows. |
| Maintainer and approval structure | See [GOVERNANCE.md](GOVERNANCE.md) — the project owner is the current sole maintainer and has final say on major changes. |
| Data privacy policy | See [PRIVACY.md](PRIVACY.md). |
| Community moderation policy | See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md#enforcement). |

## Using the Kombien name and identity

- Referring to this project by name (e.g. "built on Kombien," "a fork of Kombien") in factual, non-misleading contexts is fine.
- Do not use the Kombien name or logo as your own project's primary identity, in a way that could be mistaken for the official project.
- Do not imply endorsement, partnership, or official status without asking first (see [GOVERNANCE.md](GOVERNANCE.md) for who to ask).
- The MIT license on the code does not extend to the name, logo, or tagline — these stay reserved to the project so the identity can't be forked away from the project that carries it.

## Proposing a brand change

Brand changes (name, logo, primary colors, typography) go through a [design proposal issue](.github/ISSUE_TEMPLATE/design_proposal.md) or a Discussion, per the process in [brand/README.md](brand/README.md#brand-change-policy). Small corrections can be reviewed by any maintainer; major changes need project-owner sign-off.
